# کار یار ۴.۰ — نسخهٔ آزمایشی (kar-yar-v2)

مدیریت کارهای روزانه با رابط فارسی، تقویم جلالی، ذخیره‌سازی محلی IndexedDB، پشتیبان‌گیری و کار آفلاین. این نسخه **جدا از نسخهٔ پایدار** (kar-yar) است و روی لینک مستقل خود منتشر می‌شود تا نسخهٔ پایدار دست‌نخورده باقی بماند.

## قابلیت‌های واقعی این نسخه
- همان رابط و امکانات نسخهٔ پایدار (فیلترها، جست‌وجو، انتقال/پیگیری، سوابق، تقویم شمسی، PWA نصب‌شدنی، آفلاین، کنترل اندازهٔ متن Aa)
- **فونت فارسی وزیرمتن** (Vazirmatn v33) به‌صورت self-hosted
- **ذخیره‌سازی روی IndexedDB** (پایگاه‌دادهٔ `kar-yar-db`) به‌جای localStorage
- **مهاجرت خودکار و امن** داده‌های نسخهٔ قدیمی localStorage با پشتیبان داخل پایگاه‌داده (`_migration_backup_v1`)، اتمیک بودن، idempotent بودن و تأیید شمارش؛ دادهٔ منبع هرگز حذف نمی‌شود
- ذخیرهٔ فقط-تغییرکرده‌ها (تشخیص تغییر با مقایسهٔ محتوا) و شمارندهٔ `recordVersion` برای هر رکورد
- خروجی/ورودی پشتیبان: فرمت جدید `schemaVersion:1` با ادغام bulkUpsert + پذیرش فایل‌های پشتیبان نسخهٔ قدیمی (جایگزینی با پشتیبان خودکار پیش از عملیات)
- «خروجی لاگ برای پشتیبانی» (بافر حلقوی ۱۰۰ رویداد در IndexedDB بدون دادهٔ حساس)
- «حذف کامل داده‌ها» با تأیید دو مرحله‌ای
- «بازگردانی از نسخهٔ قبلی» در صورت وجود پشتیبان مهاجرت
- بنر آفلاین، بنر خطای ذخیره‌سازی، اعلان «نسخه جدید آماده است» با دکمهٔ به‌روزرسانی
- برچسب «نسخه آزمایشی» روی صفحه

## محدودیت‌های این نسخه (صادقانه)
- همگام‌سازی با سرور وجود ندارد؛ هر دستگاه دادهٔ مستقل خودش را دارد.
- اعلان دقیق در پس‌زمینه تضمین نمی‌شود (برای Push به زیرساخت سرور نیاز است).
- تست‌های خودکار Vitest/Playwright و CI و Lighthouse در این تحویل اجرا نشده‌اند؛ صحت مهاجرت با آزمون دستی مستند در گزارش تحویل بررسی شده است. (برنامهٔ تکمیل: docs/roadmap.md)
- ساخت پروژه بدون باندلر (no-build) است؛ فایل‌ها مستقیم روی میزبانی استاتیک سرو می‌شوند.

## نصب و اجرای محلی
```bash
cd kar-yar-v2
python -m http.server 8766   # یا هر میزبانی استاتیک
# سپس http://127.0.0.1:8766
```
(Service Worker روی localhost/HTTPS فعال می‌شود.)

## ساختار ذخیره‌سازی
- IndexedDB `kar-yar-db` v1: store `tasks` (keyPath id؛ ایندکس‌های by_dueDate/by_status/by_updatedAt) و store `_meta` (app_meta، پشتیبان‌ها، لاگ، پرچم مهاجرت)
- آینهٔ localStorage فقط به‌عنوان سازگاری/پشتیبان حفظ می‌شود و پس از مهاجرت خوانده نمی‌شود.

## پشتیبان و بازیابی
- خروجی: دکمهٔ «خروجی پشتیبان» → فایل JSON با `schemaVersion:1`
- ورودی: «بازیابی» → فایل جدید = ادغام؛ فایل قدیمی = جایگزینی (با پشتیبان خودکار `_pre_import_backup` پیش از عملیات)

## هشدار
پاک‌کردن دادهٔ مرورگر یا حذف PWA، داده‌های دستگاه را حذف می‌کند؛ به‌طور دوره‌ای «خروجی پشتیبان» بگیرید.

## استقرار
میزبانی استاتیک (GitHub Pages) با مسیر نسبی؛ Service Worker و manifest در زیرمسیر هم درست کار می‌کنند. لینک این نسخه: `https://khosravi1977.github.io/kar-yar-v2/` (نسخهٔ پایدار: `https://khosravi1977.github.io/kar-yar/`)

## گزارش مشکل
خروجی لاگ (تنظیمات ← خروجی لاگ برای پشتیبانی) را همراه شرح مشکل ضمیمه کنید.

## سنجه‌های محصولی (تعریف — در فاز اول جمع‌آوری نمی‌شوند)
- Activation: نسبت کاربران جدیدی که در ۲۴ ساعت اول ≥۱ تسک می‌سازند
- Weekly Retention: نسبت بازگشت در هفتهٔ دوم
- Task Completion Rate: تسک‌های تکمیل‌شده ÷ ایجادشده در ۳۰ روز
- Time to First Task: میانهٔ زمان بازکردن اپ تا اولین تسک
محدودیت: بدون حساب کاربری، شناسایی کاربر بین دستگاه‌ها تضمین نمی‌شود؛ هیچ دادهٔ رفتاری ارسال نمی‌شود.
